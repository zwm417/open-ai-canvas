# 逐镜生产、后期与终检

只在生成关键帧/视频/音频、制作字幕、合成、验证或交付时读取本文件。

## 1. 分镜字段

每镜使用 `SC01-SH001` 等稳定 ID，并记录：

| 字段 | 要求 |
|---|---|
| timecode | 准确起止和时长 |
| storyJob | 冲突、证据、反转、回报或 CTA |
| framing/camera | 景别、机位、构图、一个主运镜 |
| performance | 视线、动作、表情、停顿、对白 |
| product | 商品状态、可见尺度、交互和声明 ID |
| continuity | 演员、服装、手、轴线、场景、光线 |
| audio/text | 对白、环境、音效、音乐、字幕安全区 |
| transition | 与前后镜头的动作、构图或声音连接 |

同一镜头不要同时承担复杂表演、复杂商品操作和复杂运镜。拆成准备、使用、结果与反应镜头。

## 2. 关键帧

默认：

- `start`：承接上一镜的明确状态。
- `peak`：最重要动作、证据或情绪变化。
- `end`：下一镜可接的最终状态。

独立关键帧提示词写明演员身份、当前造型、商品不可变细节、商品状态、场景、动作瞬间、构图、光线、画风和禁止项。所有参考图作为真实输入传入智影原生工作台。

多宫格只用于审片。网格线、编号和多个时间状态不能进入正式图生视频输入。

## 3. 逐镜视频

每个镜头独立提交，记录任务 ID、输入、提示词、输出、状态和拒绝原因。提示词聚焦变化：

- 人物从什么动作/情绪到什么状态。
- 商品如何被拿起、打开、使用、展示或放回。
- 相机路径和速度曲线。
- 环境与物理反馈。
- 精确时长和结束构图。

检查商品形体、包装、Logo 位置、手部交互、演员身份、口型、轴线、视线、闪烁、形变和首尾衔接。不合格只重做本镜或其锚点。

## 4. 声音

在分镜阶段按层规划对白/旁白、环境声、商品操作音效、音乐意图和静默，同时锁定字幕原文、说话人和起止时间；逐镜以 `generateAudio=true` 交给支持原生同步声音的视频模型。对白以最终原生音频为准校验字幕同步。

- 音乐不能掩盖商品操作和关键台词。
- 证据镜头的关键动作应有准确同步音效。
- 保留验收合格的原生对白、环境声和商品操作音效；只有背景音乐明显不符合成片或接缝跳变时才替换/调整 BGM，不得默认移除整条原生声轨。
- 视频与必要的替换音频只通过智影原生工作台；用户音频需记录来源和授权。

## 5. 字幕与安全区

- 首帧钩子即使播放端静音也应可理解；每个由分镜锁定并交给视频模型的字幕单元短、完整、易扫读。
- 关键人物、商品、字幕和 CTA 避开平台顶部、底部和右侧控件区。
- 商品名、价格、优惠、参数和免责声明使用精确后期文字。
- 不让模型自行发明商品名、价格、优惠、参数或免责声明；对白字幕按分镜中的精确原文和时间生成，商品/法务文字使用确定性叠加。

## 6. 智影剪辑与后期合成

- Composition 从交付规格读取宽高、FPS 和总帧数。
- 动画只使用帧驱动和确定性输入，禁止 wall-clock timer、`Date.now()` 和未设种子的随机数。
- 先渲染首帧、3 秒、中段、证据、CTA 和尾帧静帧，再渲染审片版和母版。
- FFmpeg 用于编解码、抽帧、混音、响度、快启和技术检查。
- 多画幅版本重新构图字幕和人物/商品位置，不做机械裁切。

## 7. 完成验收

七层都要 PASS：

1. `facts`：所有商品与优惠声明可追溯。
2. `story`：冲突、因果、反转和回报成立。
3. `retention`：首帧、3 秒开环、中段变化和结尾回报有效。
4. `product`：商品身份、使用、证据和 CTA 准确。
5. `continuity`：演员、商品、服装、场景、道具、动作和光线一致。
6. `audio_text`：对白、音乐、音效、字幕、价格和 CTA 正确。
7. `technical`：最终 MP4 可解码，规格符合发布平台。

执行带货项目终检：
- 检查商品展示时长、痛点场景、核心卖点特写及行动召唤 (CTA) 完整性；
- 检查技术规格（画幅比例、原生音画同步、字幕安全区）；
- 技术检查通过且人工七层验收均为 PASS 后才可标记“成片完成”。

## 8. 失败定位

- 首帧弱：只重做 Hook 镜头与字幕，不重拍全片。
- 商品漂移：重做商品身份资产或受影响关键帧。
- 表演假：调整动作密度、台词长度、光线和镜头距离。
- 反转无效：回到剧本因果，不用剪辑特效掩盖。
- CTA 突兀：重写人物回报到行动的连接。
- 技术失败：保留已批准媒体，修复合成或编码。
