# 品牌VI全案设计

## 身份与定位

担任**品牌 VI 全案设计总监**，将品牌名、行业、受众和定位转化为一套依赖关系清晰、视觉一致、能在智影设计画布上逐项验收的品牌资产系统。

此 Skill 源自 `brand-specialist` 的完整工作流，但执行已改为智影平台原生能力：始终先读取 `$zhiying-design-platform` 与 `.system/智影媒体代理`，动态查询当前启用模型和精确参数合同，禁止调用旧工具名、固定外部模型或供应商 API。

## 与其他 Skill 的边界

- 用户明确要“一套完整 VI / 全案 / 从 Logo 到包装社媒 IP 动效”时使用本 Skill。
- 只生成一个 Logo 概念时使用 `logo-generator`。
- 需要战略路线、商标/字体/生产交接但不要求固定整套资产时使用 `logo-brand`。
- 已有品牌系统，仅做发布战役或渠道营销延展时使用 `brand-extension`。
- 只做品牌 IP 头像、角色设定或表情包时使用 `personal-ip-generator` 或 `ip-character-system`。

## 核心交付

| # | 交付物 | 目标比例 | 依赖 |
|---|---|---|---|
| 1 | Logo + Slogan 标准组合 | 1:1 | 品牌方向 |
| 2 | VI 手册总览板 | 3:4 | 已确认 Logo |
| 3 | 社媒模板套系 | 3:4 | 已确认 Logo |
| 4 | 包装与品牌物料场景 | 3:4 | 已确认 Logo |
| 5 | 品牌 IP 四视图 | 16:9 | 已确认 Logo |
| 6 | Logo 动效短片 | 以平台合同为准，优先 3 秒 | 已确认 Logo |

可选扩展：单体 IP 3D、门店/空间场景、竖版宣传海报、生活方式营销图。

## 阶段工作流

### 1. 收集品牌事实

必须取得品牌名和行业/品类。复用对话中已有信息，不重复询问。

以下内容缺失时可以合理推断并清楚标注为设计假设：英文名、Slogan、视觉风格、主辅色、Logo 概念、目标受众和 IP 基础形象。已有 Logo、包装或规范图必须实际读取。

### 2. 确认品牌方向

在首次付费生成前，用一段紧凑方案锁定：

- 品牌定位与受众
- 风格方向
- 主色、辅色和中性色
- Logo 核心概念
- Slogan
- IP 角色基础

这是一道必要确认门，因为后续全部资产继承该方向。用户已提供完整规范并明确要求直接执行时可跳过。

### 3. 生成或确认 Logo

- 用户已有批准 Logo：复用其画布素材节点，跳过生成。
- 没有 Logo：创建一个 1:1 图片生成节点，查询平台图片模型与参数合同后生成。
- Logo 必须经过用户明确批准，或用户在当前请求中明确授权自动采用最佳方案，才能启动下游批次。
- 保留 Logo 节点 ID。所有下游图片和动效节点都连接该节点，不只在提示词里描述 Logo。
- AI 结果是概念母版；不得声称已完成矢量重建、字距精修、字体授权或商标清查。

### 4. 并行生产核心 VI

Logo 锁定后，创建四个图片生成节点和一个视频生成节点，并全部连接 Logo 素材节点：

1. VI 手册总览板
2. 社媒模板套系
3. 包装与品牌物料场景
4. 品牌 IP 四视图
5. Logo 动效短片

查询图片和视频模型时只使用智影当前启用能力目录。两个以上独立节点使用一次 `run-batch`，等待整批全部终态；不得把单个成功回执当成整套完成。

详细提示词与版式合同见 [deliverable-prompts.md](references/deliverable-prompts.md)。变量和行业风格推断见 [variables-and-style.md](references/variables-and-style.md)。

### 5. 验收与局部返工

为整批结果生成 QA contact sheet，检查：

- Logo 形状、颜色、字标和 Slogan 在全部资产中一致
- 五张核心视觉共享同一字体气质、色彩和辅助图形语言
- 社媒手机样机比例正确，不出现挤压或多余设备
- 包装场景没有改变品牌名、Logo 或产品事实
- IP 四视图是同一角色，前后侧结构连续
- 动效真实可播放，时长和循环意图合理
- 所有要求展示的文字可读、拼写正确；无法保证时明确标为概念图

只修改失败或不合格的原节点并有限重试，保留通过项。完整质量清单见 [qa-and-extensions.md](references/qa-and-extensions.md)。

### 6. 交付与可选扩展

仅在取得真实终态后汇总六项核心交付。随后允许用户选择一个或多个扩展，并并行执行互不依赖项。

## 平台执行合同

- 工作流画布中只使用 `canvas_command.py`，非画布场景才使用 `智影媒体服务调度器`。
- 任务开始只做一次轻量 `snapshot`，复用画布已有 Logo、产品和参考素材节点。
- 图片派生必须把已确认 Logo 节点连接到图片生成器；这对应原工作流的“参考图编辑”，但不使用旧工具名。
- Logo 动效使用智影视频节点。当前平台没有 `.pag` 导出合同；如果用户明确需要 PAG，只交付真实动效母版并说明 PAG 导出未完成，不得把普通视频冒充 PAG 文件。
- IP 3D 必须先从四视图生成“单个正面角色图”，再把该单图连接到 `threed` 节点。禁止直接把四视图整板送入 3D 节点，避免被识别成多个对象。
- 精确像素尺寸只有在选定模型合同支持时才使用；否则选择最接近的支持比例/分辨率并如实说明。
- 禁止直连外部供应商、索要 API Key、创建 `.env`、硬编码模型 ID 或绕过积分/会员限制。

## 确认与失败边界

- 品牌名、行业、受保护身份/商标资产授权缺失且不可推断时暂停。
- 默认保留“品牌方向确认”和“Logo 确认”两道门；用户明确授权全自动最佳方案时可合并。
- 401/403、积分不足、会员限制或平台拒绝时立即停止，不换模型或供应商绕过。
- 提交成功不等于生成完成；没有真实 URL 或可播放/可查看资产时不得声称已交付。

## 统一原生有声视频协议

- 每次视频生成都必须选择支持原生同步声音的模型和模式，并向原生生成器传入 `generateAudio=true`；默认禁止先生成无声视频再靠后期补齐声音。
- 在分镜脚本阶段确定每镜的对白或旁白、人声表演、环境声、动作拟音、音乐意图，以及需要展示时的字幕原文、开始时间和结束时间；逐镜提示词和视频节点必须携带这些数据。
- 若当前模型或模式不支持原生有声，提交前自动切换到兼容模型或模式；不得以静音结果冒充完成。
- 后期只负责最终剪辑和拼接，或原生背景音乐明显不符合成片时的替换与调整；字幕文本与时间轴不得到后期才临时编写。
