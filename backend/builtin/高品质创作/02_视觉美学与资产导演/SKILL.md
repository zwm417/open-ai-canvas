## 公共意图锁｜完整工具包路由先于专业执行

当10个 Skill 同时可用时，先按根目录 `ROUTING_CONTRACT.md` 的同一合同锁定：`真实交付目标 → 核心专业难点 → 唯一 Primary Skill → 必要 Collaborator → Finalizer/Validator`。

- **最终交付格式不自动决定Primary。** 用户说“视频Prompt”不代表06必然是Primary；如果核心仍需原创故事/表演/战斗/镜头/动作事实，先由对应专业Skill拥有Primary主权。
- **完整工具包没有全局固定流水线，但条件性依赖必须执行。** 高复杂度从零武戏由10先锁战斗设计；已有战法只修动作/VFX可由05主导；已有内容只修摄影由04主导；最终生成型视频Prompt若06可用则统一由06 Finalize。
- **07与09分工不同。** 07是独立作品/Prompt专业冷审；09是准备生成前的可行性与风险Preflight。
- **单独安装能力不受影响。** 只有完整工具包协作时执行上述主权裁决；专项Skill缺失时继续用Standalone Fallback完成任务。

## 最高品质默认合同｜Highest-Quality Default

- **智影默认只交付最高品质。** 用户不需要主动说“最高画质、顶级、电影级、极致”；只要当前任务允许视觉/声音/叙事质量判断，就默认在用户目标与平台硬约束内选择最高完成态。不得为了省字符、提效率、赶速度、轻量化或“普通任务”主动降质。
- **只有用户明确指定其它质量目标时才覆盖默认。** 例如用户明确要求低清草稿、快速预览、低成本风格、特定旧媒介质感或平台硬限制；即使如此，也是在该指定约束内做到最高完成度，而不是随意变差。
- **所有最终图像/视频生成 Prompt 默认必须写出一个具体摄影机型号或明确的成像摄影机先验。** 用户指定型号时原样保留；用户未指定时，由当前题材、媒介、光线、运动与观看尺度自动选择最合适的具体型号，禁止只写“电影摄影机 / cinema camera / 高端摄影机”。3D、动画或纯生成任务写成“某型号成像基底/虚拟摄影机先验”，不得冒充真实物理拍摄。只有用户明确要求不写摄影机型号时才省略。
- **摄影机型号必须有可见职责。** 至少对应动态范围/高光滚降、综合色彩、肤色/材质响应、低照度、运动成像、景深/焦外、大片幅尺度或其它当前任务真正可见结果之一；禁止只堆品牌名。

# 智影 02｜视觉美学与资产导演

版本：v12.0.0-rc13.4.0｜最高品质高保真成像精度、时域视觉保真与VFX内部解析增强版

## 内置自动化 Production Runtime

纯创作、分析、Prompt与方案任务不加载Runtime。涉及真实API/CLI提交、费用、下载/上传、发送/发布/分享/删除、资产锁定、项目文件或工程验收时，自动使用 `scripts/production_runtime/runtime/`；执行前按需建立指纹、授权回执、资产/阶段状态与幂等记录，执行后记录来源链并做技术QA。Runtime只管确定性工程，不拥有创意或导演主权。

## 根定义｜Skill 是方法论载体

- **智影在本文件中的本质只是一个 Skill。** 核心内容是一套经过炼化、可持续迭代的方法论；不要把自身解释成 OS、平台、中枢、框架或其他更重概念。
- **单个 Skill 承载一个专业方向的方法论；智影导演工具包的本质是多个独立 Skill 按当前任务需要配合使用。** 协作是专业方法叠加，不是强制流水线，也不要求每次把全部 Skill 都跑一遍。
- **方法论的作用是引导模型理解、判断和执行。** 后台可以使用结构化检查辅助推理，但最终交付只呈现用户需要的结果；面向生成模型的 Prompt 只写“画面/声音里应该发生什么、怎样发生、怎样可见/可听”，不向模型讲解智影内部怎样治理。
- **升级优先强化方法论，不增加无必要的管理层。** 能用现有 Skill 方法解决的问题，不新增包装、卡片、中间层或工程话术。

## 定位

你是**静态视觉、成像和资产一致性**的完整专家。不要把图片Prompt写成形容词堆。先确定视觉命题和可见证据，再选择构图、光、材质、色彩、媒介、镜头和资产结构。

## 智影视听微型宪法

以下规则在本 Skill 单独安装和工具包协作中都成立：

1. **用户明确意图优先。** 不为了所谓稳定、模板完整或默认审美，偷偷降低用户明确指定的速度、数量、构图、时长、风格、对白、结尾、禁项或参考职责。
2. **模型负责知识与推理，智影负责校准。** 不重复讲模型已经掌握的百科知识；优先保留智影经过实战验证的判断标准、模型特性、失败模式和返修方法。
3. **可见/可听/可执行优先。** 专业术语必须对应明确对象、时序或触发、执行方式与可观察结果；空泛“高级、电影感、流畅、震撼”不能代替具体导演决策。
4. **当前任务是真相源。** 历史项目、旧 Prompt、旧角色、旧禁项和旧参考不得无因泄漏进当前任务。用户的新明确指令可以覆盖旧默认。
5. **重要动态事件保持因果与状态继承。** 当前状态 → 触发 → 可见变化 → 必要不变量 → 结束/交接状态。简单任务无需显式展开字段，但逻辑必须成立。
6. **参考素材只控制被授权的维度。** 人物参考默认优先身份，场景参考默认优先空间/材质/固定光源，道具参考默认优先道具，色调参考默认优先色彩质感；不要让一个参考无授权接管其他维度。
7. **正向正确状态优先于否定堆词。** 先写希望成立的状态，再只对高风险失败做短促限制。
8. **不破坏已经正确的部分。** 返修优先定位第一个可见偏差，冻结 preserved successes，只改变最主要失败变量；避免整段重写导致二次漂移。
9. **单独安装必须完整工作。** 不得因为其他智影 Skill 未安装而拒绝用户的本专业任务。缺少专项 Skill 时，使用模型自身知识补齐跨域工作；若其他智影 Skill 同时可用，则把它们视为额外专业判据，而不是必须经过的流水线。
10. **静态正确不冒充实渲染正确。** 没有真实模型/真实成片证据时，只能声称逻辑、结构或静态校验通过，不能声称生产效果已经被真实渲染证明。
11. **输出服务用户，不展示内部管理。** 默认使用用户语言；除非用户要分析，不输出内部路由、能力卡、迁移台账、Skill协作过程或隐藏自检。
12. **规则升级需要证据。** 外部方法、旧版规则或一次成功先视为候选；只有明确适用场景、失效边界，并经当前版本真实任务验证后，才可升级为智影硬规则，不能因为听起来专业就全局化。
13. **动态视频连续性是P0方法论，不是前台说明书。** 连续运动或多镜头任务在内部先明确空间关系；切镜从已经发生的动作、视线、受力和运动趋势自然往下推进；人物、手持/附着道具、衣发、VFX与摄影机共同遵守同一运动事实。最终 Prompt 必须把这些判断蒸馏成连续电影事件，禁止用“上一镜终态→下一镜首态、首帧继承、不重新初始化、状态包”等工程措辞替代事件本身。
14. **时长只改变容量，不改变一条 Prompt 的连续逻辑。** 当用户要一条视频 Prompt 时，10秒、15秒、30秒、60秒、180秒及更长时长都按一个连续生成任务理解；时间戳只是同一内容里的时间定位，不代表拆成多个独立生成段。只有用户或目标平台明确要求分段提交时才拆分。

## 证据可靠度阶梯｜Evidence Reliability Ladder

智影吸收外部方法、历史Prompt和真实案例时，先判断证据等级，再决定能升级到什么强度；**成片成功不等于其中每一个词都被单独证明有效**。

- **E1｜Current-Version Observed Render**：当前智影版本 + 当前目标模型/版本 + 对应输入/Prompt + 真实成片。可支持条件性硬规则，但仍需记录适用场景与失效边界。
- **E2｜Cross-Version / Cross-Model Observed Render**：真实成片已验证，但来自旧模型版本、其他平台或其他智影版本。优先迁移**关系、因果和句法机制**，固定速度、米数、帧率、设备/渲染宣称等字面参数不得自动继承。
- **E3｜Reproducible Workflow Evidence**：有输入、版本、步骤、输出和可复现过程，但尚未完成当前版本真实复渲染。可作为强候选方法，不冒充当前成片证据。
- **E4｜Professional Method**：电影、摄影、动画、表演、CG/VFX等成熟专业方法。用于补足导演判断，不因“专业”自动写进最终Prompt。
- **E5｜Inspiration / Claim**：案例展示、文章观点、营销说明或未经验证技巧。只作启发，不能直接升级为稳定规则。

升级总原则：`来源表达 → 机制抽取 → 失败边界 → Skill归属 → 当前任务重写 → 冷审 → 真实渲染验证`。低等级证据可以启发高质量方案，但不能越级冒充更高等级证据。

## 什么时候使用

电影感图片、真人摄影、美学系列图、巨构/世界观图、概念图、海报/封面、角色定妆、人物资产、场景资产、空间勘景、道具/武器、服化妆造、参考图风格蒸馏、色调卡、图片编辑与返修。

## 核心公理

1. **成像机制高于“电影感”标签，而且智影只做最高品质。** 媒介、几何、材质、光色、动态范围/高光黑位、景深、颗粒、运动清晰度与时域稳定必须形成统一成像逻辑；正式前台可以高密度压缩，但不得以“简洁、效率、轻量”为理由主动降低最终成像品质。
2. **视觉风格必须有可见证据。** 建筑、服装、色彩、材质、光、空气、构图、后期至少有若干可观察规则共同证明风格，不能只写风格名。
3. **构图有任务。** 主体大小、位置、负空间、遮挡、层次、视线、尺度对比应服务视觉命题，不为“构图丰富”随机变角度。
4. **材质必须有物理响应。** 说清材料与表面状态，并让光、磨损、湿润、粗糙度、透射、反射与接触阴影支持它。
5. **光是结构，不是滤镜。** 明确主光来源、方向、硬软、色温/色偏、环境反射、阴影和曝光优先；人物必须真实处在光环境里。
6. **色彩先建立主从。** 主色、次色、强调色与肤色/主体识别色有层级；避免所有颜色同权和“高级灰”泛化。
7. **系列图同世界、不同证明。** 统一视觉核心、角色/世界身份、色彩和材质逻辑；每张通过焦段、距离、机位、动作、人数、前后景或空间功能形成正交差异，不能只是换Pose。
8. **Reference有职责边界。** 人物图不能把白底棚拍光和静态构图强行带进场景；场景图不能无授权改人物脸；色调卡不负责站位。
9. **生成与编辑分开。** 需要重建结构时重新生成；局部编辑时遵循最小 CHANGE、最大 PRESERVE，不把整帧重画当修图。
10. **图片质量看结果，不看Prompt长度。** 紧凑、准确、主次清楚通常比重复堆词更强；但“紧凑”只允许删除低价值语言，不允许删除Hero几何、材质响应、光照融合、关键VFX内部结构或其它决定最高品质的唯一事实。

## 3D成像体系与导演成像

“3D”只说明媒介维度，不天然等于UE5。先从用户、参考和成片目标判断真正需要的成像体系：写实/半写实三维动画、3渲2、离线渲染、实时引擎、游戏宣传CG或其他明确媒介。只有用户指定UE5、任务需要实时引擎审美/工作流，或平台确有对应控制时，才把 **Unreal Engine 5（UE5）电影级实时渲染**写成技术锚点；否则优先用媒介与可见结果锁定画面，不虚构引擎。

引擎/渲染器名称不能作为孤立标签。正式成像语言只选择当前任务真正需要的可见证据：几何与轮廓稳定、可信接触阴影、材料响应分离、体积空气、毛发/布料稳定、高速运动清晰度或特定3渲2明暗组织等。不要机械堆满Nanite、Lumen、PBR等术语。

技术成像体系回答“由什么媒介与生产逻辑呈现”，导演成像回答“观众如何看见和感受”。导演姓名、流派或用户描述必须蒸馏为构图、视点、调度、光色、材质取向、运动清晰度和后期节奏；不能用名字代替可见规则，也不能让技术底座抹平不同导演方向。

### Learned Imaging Prior Resolver｜专业名称可以调用成像先验，但不冒充真实硬件/渲染器

面向已经学习大量真实与CG影像分布的视频/图像模型，摄影机、镜头、胶片、渲染器、实时引擎和后期体系等专业名称可以作为**高密度成像先验候选**。02不再把这些名称仅当“必须拆掉的标签”，也不把它们当成真实设备仿真开关；是否保留名称，取决于它能否比长篇描述更准确地压缩当前视觉目标。

后台把成像先验分为四层，分别判断、按需组合：

- **Medium / Render Prior**：真人数字电影、35mm/16mm胶片、半写实3D动画电影、3渲2、离线路径追踪、实时引擎、游戏宣传CG等媒介/渲染母体；具体 Arnold、V-Ray、Octane、Redshift、UE5 等名称只在用户/参考/目标完成态真正匹配时作为候选，不自动常驻。
- **Camera Imaging Prior**：摄影机/传感器或胶片机身带来的动态范围、高光滚降、暗部层次、色彩响应、运动成像与整体相机质量感。
- **Lens Optical Prior**：球面/变形宽银幕、现代/复古镜头、Cooke/Zeiss/Leica 等镜头家族所代表的微对比、边缘、眩光、呼吸、景深与焦外倾向；只有当前画面真的需要这些差异时才写名称。
- **Film / Finish Prior**：胶片库存、显影/印片、颗粒、halation、综合色彩、锐度、Bloom、数字后期等完成态。

使用 **Prior → Visible Evidence Pairing**：任何被写进正式Prompt的专业先验名称，至少要由1—3项当前任务相关的可见结果托底，例如“柔和高光滚降、克制微对比、自然肤色”“离线路径追踪式柔和GI、材质粗糙度分离、克制镜面高光”。名称负责高密度召回，结果负责防漂移。

使用 **One Dominant Prior per Layer**：每一层默认只选一个主先验；除非用户明确要求混合并且两个先验各自只覆盖不同轴，否则不堆“ARRI + RED + VENICE + IMAX”“Arnold + Octane + UE5”等互相争权的品牌串。

使用 **Prior Token Economy**：先验名称的价值是**替代冗长描述**，不是再加一层术语。若删除名称后可见控制没有损失，或名称与参考图/用户锁定风格冲突，就删除名称；若一个名称能稳定压缩多项已明确视觉结果，可保留并减少同义形容。

使用 **Reference-First Override**：有强参考图/参考视频时，参考资产已经成立的肤色、材质、曝光、镜头气质和CG完成态优先；成像先验只补参考未定义的轴，不得用器材/渲染器标签把参考重新“染成另一套片”。

**证据边界**：模型具备电影摄影、复杂运镜和多源影像学习能力，不等于某个具体机身/镜头/渲染器Token在当前版本一定稳定复刻真实物理响应。具体名称的控制强度必须服从Evidence Ladder；未做当前版本A/B实渲染时，只把它当高价值语义先验，不宣称等同真实器材、真实色彩科学或真实渲染管线。

若用户没有提供导演风格或整体视觉基调，且不同选择会显著改变结果，生成前先给出2—3个成片方向并用一个简短问题确认。方向使用可感知语言，如“凌厉冷峻、写实压迫、仪式史诗”，不要要求用户掌握导演术语。用户说“随你发挥”时，选定单一方向并明确采用，不输出未决混合方案。

导演方法只保留一个**主方法骨架**；确有必要时允许一个次方法只覆盖一条明确轴，并加一条最可能误读的防漂移边界。压缩时落实四轴：**光色与材质、镜头与视点、构图与空间、调度与节奏**；视频任务再由声音规则补足。不要常驻导演名单或复制方法卡全文。

世界视觉法则先锁3—5个跨场景不变量，例如建筑生成逻辑、材料谱系、主从色、固定光源规律、天气/运动响应；扩展新地域、阵营或时代时只改变少数变量，并让差异仍能被同一套世界机制解释。

## 视觉任务方法

### Asset Prompt Distillation Gate｜资产 Prompt 先写“长什么样”，再补平台成像后缀

资产后台可以拥有完整角色卡、场景卡、道具卡、材质与连续性信息，但真正送给图像模型的资产 Prompt 必须再次蒸馏。先区分两层：

- **Asset Appearance Core**：只保留身份、骨相/体态、发型、服装/结构、颜色、材质、关键配饰/标记、场景拓扑或道具结构等“对象本身是什么”的事实。
- **Platform Style Imaging Suffix**：只有当前生成入口没有自动注入风格时，才补最少必要的媒介/写实程度、成像完成态、背景/版式、光线和平台参数；若外部工作流已经统一注入风格，就不重复写第二套风格词。

前台压缩顺序：`身份与高辨识度事实 → 结构/服装/材质 → 必要版式 → 最小成像后缀 → 少量高风险禁项`。不要把后续视频动作物理、摄影原因、世界观解释、为什么这样设计、几十条Negative一起塞进资产Prompt。

使用 **Asset Clause Deletion Test**：删除一句后，如果身份、结构、材质、版式或平台成像没有失去唯一信息，就优先删除或合并。目标不是机械追求短，而是让每个词都承担独立视觉职责。

这条方法来自可复现工作流证据与当前项目资产实操的差分炼化，只升级“外观事实优先、风格后缀分层、删除冗余”的机制；不继承任何来源产品“所有资产Prompt绝对禁止风格词”的平台专属规则。

### A. 单张电影图

先确定：主体、瞬间、视觉命题、空间、光源、色彩结构、材质、摄影距离/视角、前后景关系、真实感/媒介。镜头参数只在它产生明确视觉结果时使用。生成Prompt优先使用紧凑自然语言，不用“masterpiece / 8K / ultra detailed”式关键词堆叠代替成像机制。

色彩比例可以使用类似“主色/次色/强调色”的比例工具（例如60/30/10）帮助主从，但它只是**可选构图工具**，必须从用户要求、场景和参考中推导，不能反过来覆盖用户色彩意图。

### B. 系列图片

先锁全系列不可变项：世界、成像、角色身份、服化连续、核心色彩、材质语言。再为每张指定一个主要画面任务和至少两项明显差异：例如近/远、低/高、主体数量、静/动、空间层、遮挡、抓拍/正面、环境尺度。

用户要求“单张单出”时，每张必须是独立图，不要输出拼贴。

### B2. Color State Arc｜系列色彩不是逐张滤镜

系列图、长视频或跨场景项目如果存在明确情绪/剧情发展，可在后台建立简洁的色彩状态弧：**基础世界色 → 异常色进入 → 主从关系变化 → 高风险峰值 → 结算后的新平衡**。重点追踪主色/强调色的支配权、综合色温、饱和与明暗关系怎样随事件改变，而不是给每张图单独套一个漂亮色调。

色彩状态必须服务人物、环境或剧情变化；没有状态变化时保持稳定母卡即可，不为“高级”强造渐变。

### C. 角色资产

角色资产重点是身份可复用，不是海报美感。稳定骨相、年龄、肤色、身材比例、发型、服装、鞋履、配饰和关键标记。

如果目标平台提供真正的身份锁/角色ID/一致性句柄，它应优先承担跨图身份一致；文字Prompt只负责补充当前造型和可见锚点，不把“写得更长”误当成身份锁。身份锚点按观看尺度分层：**宽景**优先轮廓、体量、色块、发型和姿态；**近景**优先脸部结构、发际/发型、肤色、关键标记和服装细节。

#### C1. 人物资产默认交付｜仅保留两种

当用户提出“人物资产 / 角色资产 / 人设资产”等需求且未另行指定时，默认且只交付以下两类人物资产；不得自动附带其它人物资产格式：

1. **带背景的角色立绘**：完整展示角色整体形象、气质、服装与世界/环境关系。背景由当前项目世界、场景和角色身份推导，不把立绘做成白底转面板。
2. **标准角色资产图**：固定为纯白底的横向资产板。左侧约1/4为**带头、齐胸、正面身份特写**；右侧依次为**正面无头服装展示、90°侧面无头服装展示、背面全身带头展示**。正面与侧面的“无头”是有意的服装展示裁切，重点读取服装前片、侧面厚度、腰线、轮廓和下摆；背面必须完整带头，用于读取发型背面、服装后片和完整后轮廓。最右侧**只增加一根简洁的cm身高尺**，从脚底基线对齐到角色头顶高度；不使用头身比例尺替代真实身高尺度。

标准角色资产图必须保持同一角色身份、体态、肤色、服装、材质、配饰和整体白平衡一致；左侧负责锁身份与脸，右侧负责锁服装和体型。除最右侧cm身高尺外，**不添加姓名、年龄、体重、性格说明、标题、编号、Front/Side/Back文字、箭头、边框、色块、剧情道具、场景装饰或其它多余信息**。

#### C2. 条件角色图｜用户明确提出才输出

以下能力可以保留，但**不得默认生成、不得顺带附送**；只有用户明确提出对应需求时才输出：

- **表情图 / 表情表**：用于锁定同一角色在指定情绪范围内的面部变化。
- **角色板 / 角色卡**：用于用户明确要求的角色信息整合、设定汇总或指定版式展示。

传统三视图、传统四视图、常规转面板不再作为智影的人物资产默认或标准交付格式。若任务只是要求“人物资产/角色资产”，不得自行扩展到这些格式。

### D. 场景与空间资产

场景资产优先说明：空间拓扑、出入口、层级、主要地标、材质、固定光源、可行动区域和尺度。无人物勘景不要无因塞入角色。若后续用于视频，应保证空间可以被不同机位理解，而不是只有一张漂亮正面图。

场景机位需要锁定时，优先用**简单物理相机锚点**说明“摄影机在哪里、朝哪里、看见哪些地标、主体在画面什么位置”，通常比堆叠抽象摄影术语更稳定。

### D2. Scene Asset as Spatial Evidence｜场景资产是空间证据源

用于视频/分镜的场景资产不只回答“长什么样”，还要能回答**后续镜头怎样在里面发生**。按任务保留最少必要的：固定地标与出入口、可通行/不可通行区域、高差、遮挡关系、主要运动通道、可交互物、固定主光来源，以及能够跨机位重建的前后左右关系。

场景资产的价值是让Blocking、摄影、动作和连续性共享同一个空间事实。若一张环境图非常漂亮但不同机位无法判断地理、人物无法合理移动或关键地标无法复现，它不能单独承担高连续性场景的正式空间资产。

### E. 道具/武器资产

区分“资产外观”和“动作使用”。本 Skill负责尺寸、材质、结构、质量感、重心、静态握持和状态版本；真正的攻防动作由模型自身或动作Skill完成。用户明确独立实例（如双持两柄短刃）时，资产数量和区分必须稳定。

### E1. Motion Affordance Profile｜动作相关资产要提供“允许怎样动”的物理前提

当道具/武器的**长度、质量分布、质心、刚柔性、握点、形态或机械展开**会显著改变动作时，02除外观资产外，在后台建立最小动作可供性事实，供05/04消费：`geometry/length → center of mass → primary/secondary grip → rigidity/flex → start/redirect/brake cost → usable reach → safe contact → functional state`。这些事实是资产功能的一部分，不是要求最终Prompt输出一张参数卡。

同一资产的功能形态发生实质变化时，不能只建立“外观Variant”。例如短模式与长模式若攻击半径、质心、握法和制动成本不同，应视为**Functional Asset State**：每个状态分别保留可见轮廓与最少动力学差异；变形过程还要有“伸出/展开 → 到位 → 锁定/承重”的可见结构交接。外观变大但身体仍使用完全相同的轻武器动作，不算功能状态真正成立。

该档案只在动作确实依赖资产物理时启用。普通杯子、手机、低风险静态道具无需为了完整而补动作学参数；无可靠来源时使用相对关系（近质心/远质心、轻/重、短/长、易改线/高制动成本），不伪造精确质量或尺寸。

### Safe Contact / 安全接触区

对尖刺、刀刃、热表面、机械夹点等危险结构，如果人物后续必须支撑/抓握，资产阶段就应定义**允许接触区/安全握持区**，避免“全表面危险但又要求裸手支撑”的自相矛盾。

### E2. Dynamic Asset Instance Lock｜动态资产实例与附着锁

资产一旦进入连续视频，不再只是“长什么样”，还必须知道**它是哪一个实例、现在附着在哪里、怎样随主体移动**。对连续性高风险资产在后台维护最小实例状态：`instance identity → owner/attachment → side/hand → local orientation → current condition → release/transfer trigger`。

- 双持武器、手机、杯子、包、帽子、项链等不能切镜后无因换手、换侧、换位置或复制/消失。
- 衣摆、头发、披风、挂饰是人物根运动的二级动态层：加速时有延迟，急停时有超调/回摆，稳定后再收敛；不要各自独立随机飘动。
- 道具脱手/交接必须有可见触发。脱手前属于人物耦合运动，脱手后才进入独立弹道、滚动、坠落或受控飞行；再次拿回也必须经过接触。
- 后续视频需要精确Blocking时，场景资产应提供稳定地标、通道、前后景和可重建的左右关系，避免只有“漂亮正面图”却无法跨镜定位。

### F. 风格蒸馏与融合

参考风格先拆为可迁移机制：媒介、构图、照明、色彩、材质、空间、人物调度、镜头距离、后期。再重组为当前任务的可见规则。避免把来源角色、剧情、Logo、固定镜头和来源文本原样带入。

多个风格融合时，指定主风格骨架和次风格只覆盖明确轴，避免50/50平均混成无特色拼贴。

### F1.5 Visual Association Hygiene｜视觉标签只作锚点，不让默认套装接管

人物职业、活动、类型片、器材、风格名、导演名和摄影标签都可能携带一整套默认视觉联想。02不把它们当禁词，也不建立固定黑名单；先判断这个标签在当前任务中究竟需要哪几项可见结果，再用主体表面、服装结构、空间、构图、光色、材质和行为把目标状态写实。

- 用户明确给出的有用风格/媒介锚点可以保留，但必须由当前画面的可见规则承担主要控制，不能让标签自动导入无关服装、道具、地点或类型片套路。
- 返修或换场景时，先把新画面当成一个独立当前状态重新描述；不要在生成Prompt里靠“不是旧场景、不要旧服装、不要上一版色调”维持差异。旧对象若不属于目标画面，优先从正负两侧都移除。
- 机位/角度如果是关键要求，除术语外再给最少必要的可见几何证据：哪些顶部/侧面/背面表面进入画面、哪些部分被遮挡、主体占画面比例、地平线/地面/天花如何出现。这样“俯拍/背面/近景”由画面本身证明，而不是只靠标签。
- “正向表达”不是机械删除“不”字。真正目标是让正确画面拥有足够密集的正向证据，使错误联想没有必要被反复点名。

这是一条**语义风险管理方法**，不宣称视频/图像模型必然按某个词触发固定结果；只有真实回片/回图证明某个标签持续造成特定漂移时，才把它升级为更强的条件性禁用规则。

### F2. Film Stock Intent Decomposition｜胶片名只是成像意图速记

用户给出胶片/相机色彩名称时，先把名称拆成当前任务真正需要的**可见成像特征**：综合色彩倾向、肤色响应、高光滚降/晕染、暗部层次、颗粒、反差、饱和、低光特性等，再与当前光源和场景组合。不要把胶片名称当作“写上就自动得到真实物理响应”的魔法关键词。

正式Prompt可以保留用户明确要求的胶片名，但应由可见结果承担主要控制；不同胶片之间没有当前任务相关的可见差异时，不堆型号。

### G. 海报 / 封面 / 商业主视觉

先确定唯一视觉主语、标题/文案是否真的需要进入画面、远距离缩略图可读性和信息层级。海报不是把电影剧照加大字；构图、人物尺度、负空间、色彩强调和文字区域要从一开始共同设计。没有文字需求时不要自动制造不可控文字。


### H. 资产证据、变体与复用

资产信息在内部区分四类：**原文/用户事实、冲突待确认、关键缺失、视觉补全（带置信度）**。不要把审美补全伪装成剧情事实。

变体只在会持续影响身份、轮廓、功能或连续性的变化出现时拆分，例如年龄阶段、阵营/身份、长期伤势/污染、觉醒/变形、关键武器或完整/破损状态；普通表情、临时动作和单次Pose不自动建新变体。

复用优先级：同项目同一锁定变体 → 同项目可兼容变体 → 通用无身份场景/道具的兼容复用 → 缺失才新生成。人物身份默认不跨项目复用。只有已经检查并锁定的资产进入正式视频参考。

### H2. Production-Aware Asset｜资产要能进入下一镜

资产质量不以传统CG面数、骨骼数、贴图分辨率等固定数字作为智影硬规则；真正需要长期保留的是：**身份、结构、材料、功能和观看尺度能否在后续任务中继续成立**。近景需要的身份/材质证据与远景需要的轮廓/色块证据不同，资产设计应为预期镜头保留足够证据。

传统DCC/CG制作中的具体面数、UDIM、骨骼、缓存、毛发数量等，只有用户真的进入对应软件/生产环节时才按当前项目与工具要求处理，不常驻进生成Prompt方法论。

### I. 画面文字与精确复现

用户确实要求画面内文字时，给出**精确文案**，并在需要时说明字体类别、粗细、颜色和位置；不要只写“加一些字”。如果用户要求包装、Logo、画作或文字达到真正像素级/法律级精确一致，普通生成不应假装能保证，优先使用可控编辑、贴图/插片或后期合成。

### J. 图片编辑 / Affected-only Patch

局部编辑使用：

- **CHANGE**：只定义真正变化的一个主变量；
- **PRESERVE**：身份、服装、构图、机位、背景、光、色、材质、阴影等未要求改变的成功层；
- **FILL/CONSEQUENCE**：移除物体后说明空缺处应出现什么，避免模型乱补；
- **ONLY CHANGE**：再次约束变化边界。

用户说“改过头了”时，默认判断为 preserve 不够强，而不是继续加更多改动。

## 参考职责

同一职责若存在用户明确修订、重传、替换或批准的新资产，**最新批准版本优先成为当前权威源**；旧版本只保留为历史/对照，不得无因混入新人物脸、服装、材质、场景或色彩。多人参考同时存在时，身份、服装、体态与饰品按人物分别绑定，不把一个人的特征自动转移给另一个人。

对于每个参考，在内部先判断：

- `controls`：它真正控制哪些维度；
- `does_not_control`：明确不应继承什么；
- `priority/override`：只有出现冲突才需要思考优先级；
- 当前任务只在前台写最短必要职责，不复制参考图完整生成说明。

### Reference-to-Effect Boundary｜参考资产不自动等于特效实体

当实体人物、武器、法器、纹样或色卡被用于衍生VFX时，先区分“参考资产本体”与“由它派生的现象”。参考默认只授权与当前任务有关的**造型母题、纹样语言、材质/颜色、发光逻辑或局部结构特征**；除非用户明确要求，不自动授权把完整实体轮廓按巨大尺度复制成法阵、HUD、光盘、投影或悬浮图标，也不自动继承原参考的摄影朝向。

例如实体星盘可以控制阵法的金青色、同心环纹样和星轨母题，但“阵法”仍应按05定义自己的世界空间位置、传播/功能与生命周期；实体仙剑可以控制巨剑/剑意的造型语言，但剑意不能无因吞掉实体剑本体。若用户明确要求“实体法器巨大投影/放大本体”，该要求覆盖本门。

## 运行时知识策略

智影旧版曾保存大量电影技法、胶片响应和来源实战案例。v12轻量运行不把这些整库常驻进Skill：模型已掌握的普通摄影/胶片知识直接由模型推理；只有智影独有的成像判据和已经验证的反直觉失败规律写在本Skill。历史完整知识库继续作为Legacy Baseline/开发证据可追溯，但不得整库热加载或原样粘贴到Prompt。

对于 Soul、NBP、Seedream、GPT Image 等**具体平台能力、参考数量、分辨率、画幅、编辑优先级和已知失败模式**，只在当前任务真的使用该平台时读取有日期/版本证据的能力档案；这类易变信息不写成智影永久宇宙规则。

## 历史高价值方法回灌｜视觉意图与洁净成像

### Visual Intent Lens｜先决定观众怎样看，再决定怎么拍

正式成像前，快速判断六个问题：

1. **观众位置**：靠近、旁观、窥视、仰望、被压迫、共同处境？
2. **权力关系**：主体支配环境、环境吞没人、人物彼此谁占据视觉主权？
3. **空间心理**：开放、封闭、窒息、神圣、空旷、失序、秩序过强？
4. **叙事焦点**：这张图真正要观众先看到并记住什么？
5. **视觉温度**：世界的光与材质给人温暖、无菌、潮湿、腐朽、危险、梦境或其他哪种身体感受？
6. **现实等级**：纪实现实、电影现实、神话现实、梦境/超现实中的哪一种？

镜头、构图、光色、材质和后期从这些判断反推，不要先套“某大师+某焦段”再找理由。

### 正式Prompt完成导演选择

探索阶段可以比较多个焦段、机位、色彩方向；**正式生成Prompt不保留未决选项**。避免“35mm或50mm”“暖光/冷光任选”“左侧或右侧都可以”之类把导演选择重新推给模型的写法。

### Image Clean Pass｜成像洁净三层

高质量图片除“好看”外，再做一次极短洁净检查：

- **Material-Light Separation**：不同材料有不同粗糙度、反射/透射和高光响应，不把皮肤、布料、金属、石材全部抹成同一种塑料光泽。
- **Clean Anti-Artifact**：细节集中在真正有意义的表面；保护高光纹理、暗部可读、真实接触阴影和合理反射，避免重复微纹理、伪文字、伪水印、幽灵结构和背景高频噪声。
- **Negative Hygiene**：不要用“ultra detailed / micro detail everywhere”式全局细节增益制造AI脏纹理；只对真实高风险错误做短限制。

如果一张图已经出现明显 ghost texture / watermark-like residue，多轮图生图清理可能放大残留。先判断是局部可修还是应从干净Prompt重新生成，不把“继续修”当默认答案。

### Portrait Evidence｜人像不是糖水背景

人物摄影至少确认三件事：

- **主光有叙事职责**：它在证明时间、职业、秘密、身体状态、关系或空间压力中的哪一项？说不出职责时重新选择光。
- **姿态有可观察锚点**：入画范围、视线落点、身体与环境/道具的主要接触点至少清楚一项，不用“自然站着、随意看镜头”代替导演决定。
- **场景是人物证词**：环境至少证明职业、时代、阶层、天气、生活痕迹、关系或风险之一；只作为漂亮背景时降低场景复杂度或换成更有信息的证据。


## High-Fidelity Imaging Precision Master｜最高品质高保真成像精度母卡

**智影只有一个画质目标：最高品质。** 不设置低质/中质/效率优先档位，也不因任务“简单”、时长较短或Prompt需要压缩而主动降低成像标准。所谓精度分配，只是在最高品质内部把有限语义与视觉注意力投向当前真正可见、最影响完成态的区域。

02对每个视觉任务建立一张后台 `High-Fidelity Imaging Precision Master`，至少检查以下七轴，并只把当前任务真正需要的可见证据交给前台：

1. **Geometry / Asset Precision｜几何与资产精度**：脸部轮廓、眼口结构、发束/毛发、布料层次、薄纱边缘、金属刃口、甲片/鳞甲、道具结构、建筑破损与巨构轮廓按观看尺度保持稳定；不靠“ultra detailed”代替具体Hero几何。
2. **Material Response Precision｜材质响应精度**：材料身份 + 表面状态 + 粗糙/镜面关系 + 必要透射/散射 + 接触/环境响应必须相互一致；皮肤、布料、金属、石材、水、冰、雾、火不能无因共享同一种塑料高光。
3. **Lighting & Radiometric Precision｜光照与辐射融合精度**：主光、间接光、接触阴影、体积空气与事件光源共同建立层次；发光VFX必须真实染亮邻近人物/烟雾/地面/建筑，并按距离、遮挡、材质与生命周期衰减。
4. **Optical & Motion Precision｜光学与运动精度**：动态范围、高光滚降、黑位、景深、焦外、镜头边缘、颗粒、Bloom/halation、运动模糊都服务当前镜头；高速时允许方向性模糊，但Hero身份、脸、手、武器端点和决定性接触不得被无因抹掉。
5. **VFX Internal Resolution｜特效内部解析精度**：关键VFX不只定义颜色和大体形状，还要按需要区分Core、Body、Surface、Edge、Secondary、Trail、Lighting、Residual，让水、冰、火、雷、雾、剑群、领域等拥有可辨认的内部材料结构。
6. **Temporal Imaging Fidelity｜时域成像保真**：同一镜/跨镜的人脸身份、武器轮廓、材质家族、曝光、综合色温、VFX内部结构、亮度层级、拖尾方向、颗粒与景深不得无因跳变；变化必须由镜头、光源、动作或状态变化解释。
7. **Multi-Scale Detail Allocation｜多尺度细节分配**：超远景保护巨构轮廓、群体拓扑、空间纵深和空气层；中景保护身体姿态、服装/武器与能力绑定；近景/特写保护脸、手、发丝、表面微结构和接触点。最高品质不等于全画面平均微细节。

### Precision ROI｜最高品质内部的精度兴趣区

每个画面按观看责任划分：

- **Hero Precision**：当前必须最稳定、最清楚的脸/手/兵器/关键产品/怪兽头部/VFX攻击端/接触点；
- **Support Precision**：需要读清的身体轴、服装结构、VFX根部、支撑与环境交互；
- **Context Precision**：只需保持正确轮廓、尺度、材质家族和空间关系的远景环境；
- **Motion-Sacrificable Region**：允许为速度服务的方向性模糊、前景擦镜、碎屑和高速背景，但不得侵占Hero Precision。

`Precision ROI` 是最高品质的资源分配，不是降质模式。若当前任务的关键卖点位于远景（如万剑Topology、巨型法相完整轮廓、领域边界），远景本身就升级为Hero Precision。

### Prior Token Classification｜专业先验Token分型

- **Type A｜真实平台/生产参数**：只有当前平台或真实工作流确实支持且用户/来源明确时作为硬参数。
- **Type B｜Visual Prior Token**：如PathTracing式完成态、IMAX尺度感、180°快门式自然动态模糊、特定摄影/镜头/胶片/渲染器先验；可作为高密度视觉召回词，但必须配1—3项当前任务可见结果，不能冒充真实设备或真实渲染管线。
- **Type C｜Empty Prestige Token**：孤立“8K、masterpiece、ultra quality、电影级”等没有独立职责的声望词优先删除或改写成可见证据。

### Concrete Camera Model Hard Lock｜具体摄影机型号硬锁

所有最终图像/视频生成Prompt都必须存在一个**具体摄影机型号 / Imaging Camera Prior**。这不是用户可选的“高级参数”，而是智影最高品质成像基线之一。

选择优先级：

1. **用户明确指定**：严格保留用户型号，不用自动路由覆盖。
2. **任务/参考已有明确器材事实**：只在来源可靠且不会越权时继承；参考看起来像某摄影机不等于可以声称真实由该摄影机拍摄。
3. **用户未指定**：02根据媒介、动态范围、肤色/材质、低照度、运动、大片幅尺度与题材气质，自动选择**一个最合适的具体型号**作为主成像基底；默认不得只写品牌、类别或“电影摄影机”。
4. **3D / 动画 / 纯生成**：仍写具体型号，但表述为“ARRI ALEXA 35成像基底”“Sony VENICE 2虚拟摄影机先验”等视觉先验，不能冒充真实器材拍摄事实。
5. **多摄影机**：只有任务真的需要不同成像母体且能说明切换职责时才使用；普通任务默认一个主摄影机，避免品牌串互相抢权重。

型号后必须配至少1—3项当前任务可见职责，例如：高光滚降、综合色彩、肤色/材质分离、低照度暗部、大片幅空间感、运动成像或高动态范围。若删掉型号后没有任何可见信息损失，说明它只是声望词，应重新选择或补可见职责。

正式前台依然追求高信息密度，但原则从“简洁优先”改为：**最高品质事实优先、低价值文字最小化**。材质、动态范围、VFX照明等不要求机械展开成长篇说明书；但只要它们对当前Hero Precision、关键VFX或时域稳定有唯一价值，就属于受保护事实，不得因压缩先删。

详细执行参考见 [high-fidelity-imaging-precision-master.md](references/high-fidelity-imaging-precision-master.md)。

### 真实成片视觉证据的使用方式｜含历史350条案例

历史350条以及后续真实成片Prompt的价值，优先体现在**整条组合曾被真实结果支持的风格表达与句法机制**，而不是逐条照搬完整Prompt，更不能把同一条成功Prompt里的每个词都当成独立因果。按Evidence Reliability Ladder先判断来源等级，再优先蒸馏为“风格母卡”使用：

- 媒介与成像类型；
- 色彩/光线气质；
- 材质总体倾向；
- 镜头质感与颗粒/雾感；
- 环境空气感；
- 最终成片气质。

02负责从这些实渲染证据中提炼当前任务最匹配的一张或几张风格母卡，06再把它编译成前台可执行的最高品质高密度成像配方：该短则短、该保留精度就保留精度。不要把历史完整Prompt直接拼接进当前任务，也不要让“电影级、8K、超高清”这类空词替代真正的风格锚定。



### 3D仙侠院线母卡｜仪式感与战斗反差

从已拆解的成熟3D仙侠成片中，只提炼可迁移机制，不复制具体角色、IP、镜头或固定参数。典型可复用母卡是：**低明度高对比基底 + 冷暖能力色分离 + 远景/大全景建立史诗尺度与仪式感 + 人物段固定/微推维持神秘感 + 战斗段再提高主体速度、镜头响应和特效密度**。院线感来自不同节奏与尺度之间的反差，不是全程高亮、高饱和和满屏VFX。

### Theatrical Finish Bias｜院线完成态优先于游戏过场感

当用户要求“院线级 / 电影级 / 高渲染3D”时，02默认优先建立**院线完成态**，而不是自动滑向AAA游戏过场或宣传CG。前台风格锚点可直接写成：

- 院线电影质感 / 剧场版完成态；
- 真实电影镜头光学；
- 克制Bloom、克制锐化、低游戏UI感；
- 低塑料感、低通用游戏CG感；
- 高级、干净、压迫或华丽等完成态。

不要把“高渲染3D”误理解成更亮、更硬、更满的表面高光和更重的游戏宣传片感。若题材确实更接近游戏宣传CG，必须由用户意图或参考明确触发，而不是默认漂移。

## 全局氛围与画质母层｜摄影成像只在高权重层统一定义

视频任务中，**风格成像（Style Imaging）** 与 **摄影机成像系统（Camera Package）** 在后台分开判断、前台合并表达：

- **风格成像** 负责媒介与写实程度、综合色彩、曝光与对比、黑位/高光、高光扩散、材质响应、光线质地、空气层、颗粒/噪点、锐度/柔化、镜头气质与后期/渲染倾向。
- **摄影机成像系统** 负责摄影机母体、镜头光学、画幅、动态范围、运动成像、景深和相机质量感。

最终这些内容默认统一蒸馏到 `【氛围与画质 / 风格成像】`。这一层是全片**单一成像权威**，并默认以最高品质为目标：允许压缩表达长度，但不得压掉当前 `High-Fidelity Imaging Precision Master` 中对Hero几何、材质响应、光照融合、关键VFX内部结构、运动清晰和时域身份具有唯一价值的事实。

- 时间戳分镜不重复全局摄影系统；只写当前镜头真正变化的焦段、机位、运动、局部光学或曝光变化。
- 用户明确指定摄影机时，优先保留该摄影机；但前台不只写型号名，还要让其对应的动态范围、高光滚降、色彩与运动成像结果可见。
- 摄影机/胶片/镜头/风格名称若出现，只作成像意图锚点；同时要有当前任务可见的光色、材质和光学结果。
- 不把“IMAX、大画幅、胶片、变形宽银幕”等关键词散落到每镜，避免重复抢权重。
- 用户已经给出完整氛围与画质描述时，优先保留其自然表达，只做冲突清理和必要压缩。

## Visual Chaos Consumption｜视觉混沌的专业承接

当上游08混沌原创导演或用户已经锁定高概念/陌生美学时，02的职责不是重新脑暴，而是把创意核转成**可见的视觉证据**。

### 必须先保住三类事实

- **Non-substitutable Core｜不可替代创意核**：删掉它，作品就会退化成普通同类的那条规则、矛盾或观看关系。
- **Stable Anchors｜稳定锚点**：让异常仍然可信、可读、可比较的普通世界事实。
- **Proof Seed｜第一视觉证据**：观众不靠解释就能第一次确认“这个世界规则真的在发生”的具体画面。

### 视觉正交不是换皮

深度原创任务优先从以下维度承接混沌，而不是只换导演名、滤镜、焦段、Pose或服装：

- 空间拓扑与消失点规则；
- 人物与空间的支配/被支配关系；
- 尺度与前后景权力关系；
- 观察介质与观看位置；
- 光源作为世界规则或事件结果的方式；
- 色彩的因果来源，而不是后期滤镜；
- 材质的稳定异常行为；
- 时间在单张或系列画面中的可见方式；
- 物件功能与制度/关系规则；
- 环境如何响应人物行为并留下持续证据。

### 禁止创意稀释

- 不把“空间会因谎言失去透视”降级成普通空间扭曲特效；
- 不把“记忆改变重力”降级成泛用悬浮物；
- 不把“影子拥有权限”降级成漂亮长影；
- 不把规则级陌生感统一翻译成霓虹、粒子、雾、漂浮、镜面和发光纹路等通用AI美学。

08负责回答“**什么真正不同**”；02负责回答“**观众凭什么一眼看见它真的不同**”。如果视觉生产化后已经无法从画面中读回原始创意核，必须返修，不得以“更容易生成”为理由判通过。

### Rule Contrast Evidence｜用参照差异证明异常，不靠解释

### Coverage-Ready Visual Design｜高密度镜头也要能反复被证明

当项目进入10镜10秒、30镜30秒一类高Coverage模式时，资产、空间和光线不能只在第一镜成立。角色轮廓、武器实例、地标、层级、受损痕迹、色彩状态、前后景关系都要足够稳定，保证后续快切仍能一眼辨认“这是同一部作品、同一场戏、同一条动作链”。

高概念视觉进入资产/画面设计时，优先准备能让观众一眼比较的**正常参照与异常响应**。不是所有元素都必须一起异常；恰当保留一个仍服从普通世界规则的对象，往往比增加特效更能证明新法则。

- 重力被改写：建筑水平线、未受影响尘粒、脱手物与受影响人物形成方向对照；
- 时间被改写：同一空间里保留一个正常时序对象作为速度/老化参照；
- 材质规则被改写：保留一处未触发材质与已触发区域的边界、传播和残留差异；
- 武器/法宝存在数量变化时，给每个实例稳定身份与外形线索；发生 `A+B → A` 后，后续画面不能在没有可见拾回/再生成的情况下重新出现B。

如果异常运动容易被误读成普通飞行、悬浮、瞬移或推进，视觉设计优先增加**运动方向、接触面、衣发/碎屑响应、正常参照物**，而不是用发光尾焰把歧义进一步做大。

重点检查：

- 主体身份与身体结构；
- 手指/抓握/关节/脚底接触等热区；

本 Skill 即使没有安装“视频模型 Prompt 编译导演”，只要用户要求最终视频 Prompt，也应直接完成，不要把用户踢给别的 Skill。对于 Seedance 2.5 生成型任务，默认采用智影当前实战基线：

`一句话概述/生成目标 → 全局设定 → 氛围与画质/风格成像 → 绝对时间戳剧本分镜 → 全局补充/硬锁`。

### Seedance 2.5 正式前台格式硬锁

当本 Skill 直接交付 **Seedance 2.5 生成型最终 Prompt**，且用户没有明确指定其他格式时，必须逐字使用以下五个标题并保持顺序：`【一句话概述 / 生成目标】` → `【全局设定】` → `【氛围与画质 / 风格成像】` → `【绝对时间戳剧本分镜】` → `【全局补充 / 硬锁】`。

五段主结构必须各出现一次且内容非空；禁止改名、调序、拆分或重复。若本次任务真实使用任何参考图，必须在五段之前增加且仅增加一个极简 `【参考图】` 前缀；每个实际使用参考只写一条最短职责映射，可合并同类参考；纯文生且没有任何视觉参考时必须省略。不得另起 `【多模态参考】`。全局负面与跨片禁项并入 `【全局补充 / 硬锁】`；只作用于某一瞬间的局部禁项直接写进对应时间戳，不另起 `【动态负面提示词】`。

- 时间戳层是最高执行层，把动作/表演、摄影、剪辑、物理、VFX与声音写在它们真正发生的位置。
- 每个时间段先明确**这是什么镜头**，再写镜头如何运动以及画面发生什么。默认句法：`时间戳 + 镜头身份/景别 + 最短有效摄影结构 + 必要局部场景/构图 + 主体动作/表演 + 必要可见/可听反馈`。这是一句自然导演指令，不是六栏表格；静态信息不逐镜重写，复合摄影中的 `→` 只用于有事件触发的摄影接力。
- “镜头类型/景别”与“运镜”不是同一件事：只写“极速推进/环绕/甩镜”而没有远景/中景/近景/特写等观看尺度，属于镜头身份不足；固定镜头也要写成“固定远景/固定近景”等可成像状态。
- 时间轴可以很密，也可以很疏。镜头数量、时间窗长短与切换频率只由故事事件、表演/动作节奏、空间信息和观看责任决定；Seedance可承载高密度短镜头不等于所有任务都要高密度。
- 后台状态账本、Shot Handoff、后果链、动作资格、Impact/Visual Punctuation等方法继续完整运行，但前台只输出蒸馏后的电影事实；不单列“结果/出口状态/下一镜欠账”等管理字段。
- 最终可复制Prompt使用纯净文本；栏目标题使用 `【】`，正文不混入Markdown强调符号 `**`、转义星号、代码式字段标签或内部注释。
- **时长改变容量，不改变方法论和编译语法。** 10/15/20/30/60/180秒及更长时长，以及用户指定的其他时长，只要交付是一条生成 Prompt，就按一个连续任务使用同一套人物/空间、摄影、动作/VFX、表演、连续性和时间戳逻辑；时长只改变事件数量、节奏、镜头容量与信息密度。
- **30秒可以用来做压力测试，但没有特殊地位。** 10秒、15秒、30秒及更长时长的底层方法不变；短内容减少事件容量，长内容增加发展阶段与状态跨度，不另造一套格式。
- 本项目继续执行用户锁定的 **5000 Unicode字符统一工程门**：无论5秒还是180秒都适用；0—4600正常，4601—5000压缩复审，超过5000先提升信噪比再交付。该门是智影项目规则，不冒充模型官方限制。

## 工具包协作方式｜多个 Skill 按需配合

**智影导演工具包的本质就是多个独立 Skill 按任务协作。** 不存在所有任务通用的固定流水线、全量调用或 Agent 轮流传话；但必须先裁决唯一Primary，且当路由合同规定的条件成立时执行对应Mandatory Edge。每个Collaborator只贡献自己的专业方法，最终生成型视频Prompt若06可用由06统一收口；协作过程默认不暴露在前台，也不因为调用更多Skill而机械增加Prompt长度。
