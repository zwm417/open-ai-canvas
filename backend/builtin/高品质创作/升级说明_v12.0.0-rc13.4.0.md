# 智影视听导演 v12.0.0-rc13.4.0 升级说明

## 版本定位

本版是rc13.3.1路由Hotfix之后的**最高品质成像精度差分升级**。不新增Skill，不重构路由，不重做战斗奇观、Combat–VFX、动作物理、摄影证明、五段Prompt或5000 Unicode工程门；核心目标只有一个：把“智影视听导演只做最高品质”从偏好升级为10 Skill共同硬合同，并解决高完成度CG/真人/广告/仙侠任务中“画面正确但成像精度被过度压缩”的问题。

## P0默认合同

1. **Highest-Quality Default**：智影视听导演默认只做当前用户目标与平台硬约束内的最高品质，用户无需主动说“最高画质/顶级/电影级”。
2. **No Automatic Quality Downgrade**：不得为了省字符、提速度、稳定性、轻量化或“普通任务”主动降质。只有用户明确指定其它质量目标时才覆盖默认，覆盖后仍在该约束内做到最高完成度。
3. **Concrete Camera Model Hard Lock**：所有最终图像/视频生成Prompt默认必须出现一个具体摄影机型号/具体型号成像基底。用户指定则保留；用户未指定则按题材、媒介、动态范围、低照度、运动和观看尺度自动选择一个最合适的具体型号。
4. **Camera Model Must Prove Imaging**：摄影机型号必须绑定可见成像结果，不能只堆品牌。3D/动画/纯生成将其作为虚拟摄影机/成像先验，不冒充真实物理拍摄。只有用户明确要求省略型号时才省略。

## 02｜High-Fidelity Imaging Precision Master

新增并正式保护七轴：

- Geometry / Asset Precision
- Material Response Precision
- Lighting & Radiometric Precision
- Optical & Motion Precision
- VFX Internal Resolution
- Temporal Imaging Fidelity
- Multi-Scale Detail Allocation

新增Precision ROI：Hero / Support / Context / Motion-Sacrificable。最高品质不等于全画面平均锐化；不同景别把最高精度交给不同观看责任。

同时新增具体摄影机型号硬锁：用户未指定时02必须自动选择一个具体Camera Model / Imaging Camera Prior，并附至少1—3个当前任务可见职责。

## 04｜Shot-Scale Precision Responsibility + Camera Body Identity

新增：

- Extreme Wide / Wide / Medium / Close不同景别的最高品质责任；
- Hero Detail Protection：高速允许非Hero区域方向性模糊，但关键脸、手、武器端点、接触点或主VFX结构不能无因糊失；
- Precision Handoff：跨尺度切镜时精度主权随观看责任迁移；
- Camera Body Identity：具体摄影机型号作为全片成像母体，默认跨镜保持同一主机身，焦段/机位/运动可以变化。

## 05｜VFX Internal Resolution + Radiometric + Temporal Fidelity

主VFX按需要建立Core / Body / Surface / Edge / Secondary / Trail / Lighting / Residual内部解析层，不机械全开，也不允许复杂能力退化成单层发光色块。

VFX必须真实进入世界光照：照亮人物、烟雾、碎屑、地面/建筑并随距离、遮挡和生命周期衰减；同一能力的内部材料、亮度层级、Anchor、传播方式、Trail和Residual跨帧保持身份。

## 06｜Maximum High-Fidelity Semantic Density

把“最大可执行语义密度”在画质维度升级为：**不降低品质，只优化最高品质的表达效率。**

Protected Imaging Semantics包括：

- Hero Geometry / Material Response
- 关键VFX内部结构
- Radiometric Integration
- Hero Detail ROI
- Motion Clarity
- Temporal Imaging Identity
- Scale-dependent Detail
- Concrete Camera Model / Imaging Camera Prior

4601—5000 Unicode压缩复审先删Empty Prestige Token、同义质量口号、无对象技术名、参考已承担的重复静态描述、逐镜重复母卡和非Hero低收益微纹理；不得默认先删上述受保护成像事实。

摄影机型号不新增独立前台栏目，固定编译进现有 `【氛围与画质 / 风格成像】`，五段主结构不变。

## 07 / 09｜双重质量门

07新增：IMAGING_PRECISION_UNDERSPECIFIED、HERO_DETAIL_PRIORITY_LOSS、MATERIAL_RESPONSE_FLATTENING、VFX_INTERNAL_RESOLUTION_COLLAPSE、RADIOMETRIC_INTEGRATION_FAIL、TEMPORAL_IMAGING_DRIFT、MULTISCALE_DETAIL_MISMATCH、GLOBAL_MICRODETAIL_NOISE、MOTION_CLARITY_ROLE_CONFLICT、PRECISION_COMPRESSION_LOSS，以及CAMERA_MODEL_MISSING / CAMERA_PRIOR_NO_VISIBLE_RESULT / CAMERA_MODEL_DRIFT。

09保留原有Generation Preflight核心方法与references，只新增最高品质最终门：用户未明确要求省略时，最终生成Prompt缺具体摄影机型号或为了“更稳/更短”主动删除唯一高保真事实，不能通过Preflight。

## 冻结项

- 10 Skill数量与rc13.3.1路由合同不变；
- Exactly One Primary / Collaborator / Finalizer / Validator不变；
- 24题Routing Regression继续保留；
- rc13.3.0 Combat Spectacle / Visual Saturation / Frame Occupancy / Continuous Motion Floor不变；
- rc13.2.0 Maximum Executable Semantic Density / Combat–VFX Co-Design / Frontend Director Sentence v4不变；
- Seedance 2.5 Subject→Action→Scene→Style→Camera→Audio语义映射不变；
- 有参考时极简【参考图】前缀 + 固定五段最终Prompt不变；
- 01—07 Production Runtime保持原方法，不因成像升级改写工程运行时。

## 证据边界

本版的成像精度机制来自当前智影视听导演已有Style/Camera Imaging基础、用户提供的多套实战高完成度Prompt中的可迁移视觉关系，以及本轮差分审计。外部Prompt可证明“这些高密度成像关系被真实工作流使用过”，但没有对应当前Seedance版本的同资产A/B回片时，不把某个摄影机名、渲染器名、8K/60fps等单词单独升级成E1因果。摄影机型号在本版首先承担**高密度成像先验与用户硬要求**，同时必须配可见结果。
