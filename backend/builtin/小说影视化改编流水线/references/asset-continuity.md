# 资产与跨集连续性

只在建立、生成、审核或复用角色、服装、场景、道具和 3D 资产时读取本文件。

## 1. 稳定 ID

资产 ID 不随文件名、版本或集数改变：

- 角色身份：`CHAR-001`
- 角色造型状态：`LOOK-CHAR001-01`
- 场景：`LOC-001`
- 道具：`PROP-001`
- 载具：`VEH-001`
- 3D/特殊资产：`ASSET-001`

生成版本使用后缀 `-v001`，批准版本由 manifest 的 `approvedVersion` 指向。不要通过覆盖文件“更新”资产。

## 2. 角色圣经

角色身份与剧情状态分开：

```json
{
  "id": "CHAR-001",
  "identity": {
    "ageRead": "",
    "faceGeometry": "",
    "body": "",
    "skin": "",
    "hair": "",
    "immutableMarks": [],
    "doNotChange": []
  },
  "looks": [{
    "id": "LOOK-CHAR001-01",
    "wardrobe": [],
    "accessories": [],
    "hairState": "",
    "makeup": "",
    "injuries": [],
    "effectiveFrom": "",
    "effectiveUntil": "",
    "cause": ""
  }],
  "performance": {
    "baseline": "",
    "gestureVocabulary": [],
    "forbiddenCaricatures": []
  }
}
```

身份参考应包括正面、左右 3/4、侧面、全身比例、表情范围和中性光。批准前检查不同角度是否仍是同一个人。

## 3. 场景圣经

场景不是一张氛围图。至少定义：

- 平面拓扑、入口、窗、固定家具和人物运动路线。
- 主光源方向、色温、时段、天气与可变状态。
- 关键材质、尺度参照、前中后景和可复用机位。
- 与相邻空间的关系，以及哪些镜头能自然连接。

场景变体必须说明变化原因，例如白天到夜晚、完好到损坏、整洁到凌乱。

## 4. 道具生命周期

每件剧情道具记录：外观、尺寸、材质、功能、初始持有者、左右手、出现/转移/损坏/遗失/回收镜头。道具状态变化必须由镜头事件触发。

## 5. 生成依赖顺序

1. 用户提供的真实 IP/角色参考入库并审核。
2. 生成并批准角色 identity sheet 与核心造型。
3. 生成并批准核心道具和必要 3D 资产。
4. 生成场景拓扑与环境状态。
5. 用角色 + 造型 + 场景 + 道具做组合测试。
6. 组合测试通过后才批量生成独立关键帧。
7. 关键帧通过后才逐镜生成视频。

所有生成请求都通过智影原生工作台，并显式传入所需参考图。不能仅在文字中写“保持上一张一致”。

## 6. 连续性矩阵

为每镜维护：

| shotId | characters | looks | locationState | props/hand | injuries | screenDirection | eyeLine | light | source |
|---|---|---|---|---|---|---|---|---|---|

镜头批准前与上一镜、下一镜及同一剧情时间点的其他集对比。状态冲突必须标为：

- 有剧情原因并已有生效镜头。
- 有剧情原因但缺少过渡镜头。
- 无原因的连续性错误。

后两类不能直接批准。

## 7. 失败重做

识别最小失败范围：

- 身份漂移：重做角色变体或本镜关键帧，不重写剧本。
- 场景轴线错误：调整分镜或相关相邻镜头。
- 道具状态错误：修正产生错误的首个镜头并顺推检查。
- 服装跨集错误：修正 look 生效范围和受影响镜头清单。

保留失败任务 ID、输入参考、提示词、输出和拒绝理由，防止同一错误重复发生。
